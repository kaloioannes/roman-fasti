# 王朝专题与有出处的关系图

`dynasties/` 汇集三卷帝国档案现有的55项王朝、家族及无固定归组，保留原标签、类别、说明、分类来源和全部成员。王政和共和国没有被追加皇室归组。所有分类档案可读成员、已收录称号阶段、明确关联事件和同一时期背景。

尤利乌斯—克劳狄、弗拉维、科穆宁三组另有主题叙述、关键事件、98条逐边编订关系与31位辅助人物。科穆宁涵盖1081年的联盟和收养、约翰二世至曼努埃尔的指定继承，以及阿莱克修斯二世与安德罗尼科斯的权力转换。这是有明确查阅范围的关系网络，不声称穷尽所有旁支。其他52份档案明确标示亲属边尚未编订。

## 阅读与链接

- 目录支持中文、拉丁文、希腊文去重音检索；分卷、原归组类型和编订状态可组合筛选。姓名只用于查找，不用于建立关系。
- `#topic=empire--julio-claudian` 为稳定专题；`&type=adoption` 查看收养图层；`&type=all` 按列表对读全部关系；`&relation=adoption-claudius-adopts-nero` 定位一条边；`&node=livia` 打开人物节点。图中文字和连线均可用键盘打开，路由后焦点定位到目标。
- 五类关系分别是亲生父母→子女、婚姻、收养者→养子女、政治指定／安排、帝位承接。图层使用不同颜色和线型；婚姻无箭头。图的位置与列只为排版，不是年代或辈分。支持缩放、横向滚动、手机等价列表。
- `focus` 只保留某人的直接边，不推导祖孙、兄弟或表亲。`status` 区分明确记载和异说／传闻。`at` 使用带符号历史年份，无0年；裸整数明确解释为公元年。未定年边仍保留并标示。
- 日期表示关系、缔结、指定或交接的时间。年精度的婚姻缔结不表示婚姻只持续一年；未知起讫不由生卒或帝期推算。不补1月1日。
- 原卷人物和跨卷总档案反查专题。奥古斯都沿用人工跨卷身份；阿格里帕以显式ID、身份检查连接已有共和国档案。辅助人物不会因进入图而取得帝号或新增任职，原王朝筛选链接仍保留。
- 任期逐段列出身份、原可读日期、端点精度、说明和来源，保留复位、共帝、争位和流亡。年度链接限制在原卷内。相邻卷重复收录的称号不累计成时长。
- 事件分为人工选取的关键节点、原事件显式人物关联、同一时期背景。背景按任期窗口汇集，可能是年度摘要，不能当作皇室参与的证据；进入事件档案查看日期、人物角色与来源。
- 专题和每条关系有稳定链接，可复制当前视图。JSON导出保留全部关系、节点、任期、引用、查阅范围、版本与许可。剪贴板受限时选中链接供手动复制；存储受限仍可阅读。主题偏好沿用全站。

## 实际查阅与材料边界

本次实际读取13项古代／中世纪电子译文记录、4篇Andrew Stone署名研究。逐项作者、译本、网址、阅读范围、核对日期及局限保存在源资料中。

- Rolfe译苏埃托尼乌斯：《奥古斯都传》62—65、101；《提比略传》4、7、15、23；《卡利古拉传》1、7、12—14；《克劳狄传》1、10、26—27；《尼禄传》5—8；《韦斯帕芗传》3、25；《提图斯传》4、6、9；《图密善传》1—3、17.3。
- Church／Brodribb译塔西佗《编年史》I.3、I.5—8、XII.1—8、XII.25—26、XII.41。
- Dawes译安娜《阿莱克修斯传》II.1—2、II.5、III.1—4、III.6—8、VI.8。作者也是关系节点，明确说明其皇室立场。
- Andrew Stone的DIR论文John II、Manuel I、Alexius II、Andronicus I，定位到正文小节。直接读取的是研究，其引述的霍尼亚提斯、金纳莫斯及颂辞属于间接路径，未声称通读这些版本。

没有校勘原文手稿或通读未获取的付费研究。分类来源标“沿用原卷引用；本次未重新核读”，不算本次直接核读来源。每条关系保存来源、卷章／小节和支持的论断，不给出百分比可信度。

老德鲁苏斯为奥古斯都亲生子的传闻，不覆盖老提比略·尼禄为父的明确记载。图密善声称父亲遗嘱给予共同权力，不改写其原帝号任期。提图斯传4.2所述女儿的母亲不凭婚姻先后连边。Stone旧论文中匈牙利王位简述的错误亲属判断不采入；研究中的具体帝期与原卷不同时保留原卷校订，例如1119／1122共帝加冕取舍。指定、共同帝号、实际主政、最终继位不互相等同。

## 模型与维护

编辑 `data-source/dynasties/relations.json`，不迁移五卷schema。

- `sources`：稳定来源ID与查阅记录。直接正文、节选、间接引述分列；间接记录必须注明经由材料。原分类来源由构建生成 `inherited:` 命名空间。
- `nodes`：有出处的辅助人物。已有档案用显式 `(period, person)` 和 `identityCheck`；未建立跨卷身份的同名人物不合并。原人物跨卷合并只使用PR04人工身份表。
- `topics`：键为 `<period>--<dynasty>`，包含主题叙述、别名、关键事件ID和关系边。原分类目录由源卷投影，不能在此覆盖标签。
- `edges`：稳定ID、`from/to`、枚举 `type/status`、`date`、说明和 `references`。非明确状态要求 `dispute`；未定年端点必须为空；引用必须有 `source/locator/supports`。明确血缘执行无环校验；继位可以复归，不套用此规则。
- `relatedTopics`：人工指定的跨卷或姻亲入口，不按相同标签文本自动合并。

重建顺序：五卷 → 人物、事件、时间轴 → 王朝 → 搜索。发布构建自动重建，输出 `data/dynasties/index.json` 及小型 `navigation.json`。原人物只请求导航，独立缓存、共享在途请求、20秒超时、失败可重试；原正文与地图不重载。异步回链检查插槽仍连接，快速换路由后不写入旧页。

```sh
python scripts/build_dynasties.py
python scripts/build_search.py
npm run test:dynasties
npm run validate
npm run build
npm run validate:release
npm run test:dynasties-ui
```

源资料及两个产物一起提交。边ID不随修正文案改变；身份、关系结论的变更必须显式编辑证据，不按姓氏或模型推断批量连边。页面只用DOM文字节点和SVG，不把来源或路由文本插入HTML。

数据回归保全全部原分类和任期，检查确定性、双向入口、跨卷身份、事件归类、出处及错误编辑。浏览器回归覆盖55份专题、全部关系层、图形与列表数量一致、键盘、直链刷新返回、筛选、未知值、事件入口、下载、复制回退、独立失败恢复、路由竞争、存储受限、根路径／Pages及320／390／768／1440明暗布局。
